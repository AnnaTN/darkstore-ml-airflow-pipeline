# О проекте

Эффективность компании «Прилавок», новой сети дарксторов, специализирующейся на быстрой доставке продуктов и товаров повседневного спроса, критически зависит от качества управления запасами. 

В отличие от обычных магазинов, где покупатель может заменить отсутствующий товар аналогом, в онлайн-доставке отсутствие позиции в заказе приводит к его отмене, из-за чего клиент останется недовольным. Сейчас планирование закупок происходит централизованно и вручную. Отсутствие автоматизированного прогнозирования и управления запасами создаёт три критические проблемы - дефицит товаров ведёт к потере выручки, избыточные запасы ведут к списаниям товаров, операционная неэффективность. 

Задача в рамках проекта — создать полноценный ML-пайплайн для прогнозирования продаж по батч-признакам. Он должен включать:
1. Обучение модели на исторических данных с мониторингом стабильности признаков с помощью PSI.
2. Сохранение артефактов модели в S3.
3. Реализацию пайплайна в инференсном срезе признаков в Airflow с загрузкой данных из Postgres и записью результатов обратно.


## Описание данных

Данные хранятся в PostgreSQL и организованы в виде нескольких таблиц:

1) Таблица `sales`

Содержит исторические данные о продажах. Период: февраль 2023 г. — октябрь 2025 г.

Признаки:

- `store` - номер даркстора (1–45);
- `dept` - номер отдела внутри даркстора (1–99);
- `date` - неделя, представленная датой в формате YYYY-MM-DD;
- `weekly_sales` - недельные продажи отдела в конкретном дарксторе, руб. Целевая переменная;
- `is_holiday` - признак праздничной недели: True или False.

Особенности:

- в `weekly_sales` встречаются отрицательные значения;
- в данных есть пропуски для некоторых комбинаций «даркстор — отдел — неделя»;
- некоторые отделы могли быть закрыты или только открыты в определённые периоды.

2) Таблица `stores`

Содержит информацию о дарксторах.

Признаки:

- `store` - номер даркстора (1–45);
- `dept` - номер отдела внутри даркстора (1–99);
- `type` - тип даркстора;
- `size` - размер даркстора в условных единицах.

3) Таблица `features`

Содержит признаки, связанные с внешними факторами.

Признаки:

- `store` - номер даркстора (1–45);
- `dept` - номер отдела внутри даркстора (1–99);
- `date` - неделя, представленная датой в формате YYYY-MM-DD;
- `temperature` - средняя температура в регионе за неделю;
- `fuel_price` - средняя цена топлива в регионе за неделю;
- `factor1` - `factor5` - анонимизированный показатель рекламных акций и скидок;
- `cpi` - индекс потребительских цен;
- `unemployment` — уровень безработицы в регионе.

Особенности:

- столбцы `factor1` - `factor5` содержат большое количество пропусков, так как акции проводятся не каждую неделю;
- все признаки доступны на момент прогноза, утечек данных нет.

4) Таблица `plan`

Содержит данные для инференса, на которых нужно использовать обученную модель для предсказания. Период: ноябрь 2025 г. — июль 2026 г.

Признаки:

- `store` - номер даркстора (1–45);
- `dept` - номер отдела внутри даркстора (1–99);
- `date` - неделя, представленная датой в формате YYYY-MM-DD;
- `is_holiday` - признак праздничной недели: True или False.

Особенности:

- структура полностью совпадает с таблицей `sales` - за исключением целевой переменной;
- столбец `Weekly_Sales` отсутствует - это целевая переменная, которую нужно предсказать по данным таблицы, используя уже обученную модель.

## Описание признаков

Среды признаков были использованы:

- исходные: `store`, `dept`, `is_holiday`, `type`, `size`, `factor3`, `factor5`;
- временные из `date`: `month`, `quarter`;
- исторические по группам `store` - `dept`: среднее предыдущих продаж `avg_sales_before`, лаги за 1, 2 и 4 недели, скользящие средние за 2 и 4 недели.

Исторические признаки рассчитаны через shift(), чтобы исключить утечку целевой переменной. По результатам PSI исключены нестабильные признаки: `temperature`, `fuel_price`, `factor1`, `factor2`, `factor4`, `cpi`, `unemployment`, `year`.

## Логика обучения

Данные были разделены по времени:

- обучение: февраль 2023 г. - август 2025 г.;
- валидация: сентябрь - октябрь 2025 г.

Использована модель `CatBoostRegressor` с гиперпараметрами:

- `random_state` = 42;
- `early_stopping_rounds` = 200;
- `use_best_model` = True;
- `verbose` = 200.

Качество модели оценивалось по метрикам MAE, RMSE и R². Полученные результаты:

- `MAE` — около 1394;
- `RMSE` — около 2929;
- `R²` — около 0,98.

Стабильность признаков оценивалась с помощью PSI. Признаки с PSI ≥ 0.2 были исключены: `temperature`, `fuel_price`, `factor1`, `factor2`, `factor4`, `cpi`, `unemployment`, `year`. Признаки `month` и `quarter` сохранены для учёта сезонности, несмотря на высокий PSI.

## Архитектура пайплайна

DAG включает следующие задачи:

- `load_data` - объединяет таблицы `sales`, `plan`, `stores` и `features` из PostgreSQL во временную таблицу `inference_data_temp`;
- `preprocess_features` - обрабатывает данные, создаёт временные, лаговые, агрегированные признаки и отбирает строки датафрейма;
- `load_model` - загружает обученную модель catboost_model.pkl из S3;
- `run_inference` - выполняет пакетное прогнозирование и обрабатывает отрицательные прогнозы;
- `save_predictions` - записывает результаты в таблицу `predictions` в PostgreSQL.

Источником данных являются таблицы из PostgreSQL. Модель хранится в объектном хранилище S3 Yandex Cloud. Подключения и секреты настраиваются через Airflow Connections и Variables.

## Инструкция по запуску

1. Установить зависимости:
```
pip install -r requirements.txt
```

2. Создать файл .env с параметрами подключения к PostgreSQL и S3:
```
DB_NAME=
DB_HOST=
DB_PASSWORD=
DB_PORT=
DB_USER=

S3_ACCESS_KEY_ID=
S3_SECRET_KEY=
S3_BUCKET=
```

3. Запустить все ячейки `model_training.ipynb`. Модель будет обучена и сохранена в `S3` под ключом `catboost_model.pkl`.

4. В Airflow создать Connection `postgres_sales_db` с параметрами PostgreSQL.

5. Создать Airflow Variables:
```
s3_access_key = 
s3_secret_key =
s3_bucket_name = 
s3_model_key = catboost_model.pkl
```

6. Поместить batch_inference_dag.py и preprocessing.py в одну папку dags.

7. В интерфейсе Airflow найти DAG `sales_prediction_batch_inference` и нажать Trigger DAG.

8. После успешного выполнения проверить результаты с помощью SELECT-запроса.
